# by-data-tools — боковое меню и номер паспорта: дизайн

**Дата:** 2026-09-28
**Статус:** на согласовании
**Опирается на:** `2026-09-28-by-personal-number-design.md` (ядро, форматы, приватность, стиль)

## Цель

1. Превратить одностраничный инструмент в набор разделов с **левым боковым меню по категориям** —
   основной навигацией по функциональностям.
2. Добавить раздел **«Номер паспорта»** (серия + номер): валидация, разбор, генерация (полностью
   случайная или по полям) в двух форматах — паспорт образца 1996 г. и биометрический паспорт.

**Критерий успеха:** из меню открывается любой реализованный раздел, ссылка на раздел с выбранным
форматом работает при открытии в новой вкладке; сгенерированный номер паспорта проходит валидацию
своего формата; обещания приватности первой фичи сохраняются для всех разделов.

## Решения, принятые в диалоге

- Меню показывает **и реализованные, и планируемые** пункты; планируемые неактивны с пометкой «скоро».
- Категории и пункты: **Документы** — «Идентификационный номер», «Номер паспорта»;
  **Организации** — «УНП» (скоро); **Финансы** — «IBAN / номер счёта» (скоро);
  **Контакты** — «Телефон» (скоро).
- Биометрический паспорт — **в том же разделе**, отдельным форматом через переключатель
  (структура та же, отличаются только серии).
- Серия не из известного списка — **предупреждение**, номер валиден.
- Контрольная цифра MRZ номера документа показывается в разборе и при генерации.
- ID-карта — вне рамок (другая MRZ, TD1; серия не описана).

## Навигация

### Маршруты

Hash-маршруты (GitHub Pages отдаёт только статику, hash не требует настройки сервера):

| Маршрут | Раздел |
|---|---|
| `#/personal-number` | Идентификационный номер |
| `#/passport-number` | Номер паспорта |

- Формат раздела — параметр внутри hash: `#/passport-number?format=biometric`.
- Пустой или неизвестный маршрут, а также маршрут пункта «скоро» → переход на
  `#/personal-number` через `history.replaceState` (без лишней записи в истории).
- **Обратная совместимость:** старые ссылки `…/by-data-tools/?format=legacy` (query вне hash)
  открывают `#/personal-number?format=legacy`, после чего query вне hash удаляется.
- Смена раздела обновляет `<h1>` и `document.title` (`<раздел> — by-data-tools`) и переводит
  фокус на `<h1>` (доступность для скринридеров).

### Боковое меню

Material 3 navigation drawer, собственная вёрстка на токенах M3 (в `@material/web` 2.5 navigation
drawer нет среди стабильных компонентов):

- **≥ 840px** — постоянная панель слева шириной 280px, контент справа.
- **< 840px** — модальная панель: кнопка ☰ в верхней панели открывает, закрывают выбор пункта,
  клик по затемнению (scrim) и `Escape`. При открытии фокус переходит в панель, при закрытии
  возвращается на ☰.
- Категория — заголовок секции (`<h2>` малого размера, `on-surface-variant`).
- Пункт — ссылка `<a href="#/…">`; активный пункт — заливка `secondary-container` и
  `aria-current="page"`.
- Пункт «скоро» — не ссылка: `<span aria-disabled="true">` с приглушённым цветом и меткой «скоро».
- Разметка: `<nav aria-label="Разделы">`.

## Реестр разделов

`src/tools/index.ts` — единственное место, где описаны категории и пункты:

```ts
interface Tool {
  id: string;              // 'personal-number' — он же маршрут
  title: string;           // 'Идентификационный номер'
  category: CategoryId;    // 'documents' | 'organizations' | 'finance' | 'contacts'
  formats: FormatModule[]; // пустой массив = «скоро»
}
```

Категории — упорядоченный список `{ id, title }`. Порядок пунктов в меню — порядок в реестре.
Новый раздел = новая запись в реестре + модули форматов; UI не меняется.

Страница раздела собирается из существующих частей: переключатель формата (скрыт, если формат один),
плашка `notice`, карточки «Проверка и разбор» и «Генерация». Подсказка «похоже на другой формат»
ищет только среди форматов **текущего** раздела.

## Состояние формата

- Отдельно для каждого раздела: hash-параметр `format` и ключ `localStorage`
  `by-data-tools:format:<tool-id>`.
- Приоритет: параметр в hash → сохранённое значение раздела → первый формат раздела.
- Для «Идентификационного номера» при отсутствии нового ключа читается старый ключ
  `by-data-tools:format` (пользователи первой версии не теряют выбор).
- Номер по-прежнему **не попадает** ни в URL, ни в `localStorage`. Единственный модуль, который
  пишет в URL/хранилище, — `src/ui/formatState.ts` (гарантия из первой фичи, тест приватности
  расширяется на новые файлы, включая роутер).

`FormatId` перестаёт быть закрытым объединением двух значений и становится строкой; допустимость
проверяется по списку форматов конкретного раздела.

## Номер паспорта

Общая структура обоих форматов: **2 латинские буквы (серия) + 7 цифр**, например `MP1234567`.
У самого номера контрольной цифры нет.

### Контрольная цифра MRZ

По ICAO Doc 9303 (часть 3, 4.9): веса `7,3,1` циклически, цифры как есть, `A=10 … Z=35`,
заполнитель `<` = 0, сумма mod 10. Номер документа в MRZ паспорта — 9 символов, белорусский
номер занимает их ровно. В разборе и генерации показывается фрагмент MRZ: `MP1234567` + цифра.

Ядро: общая функция `icaoCheckDigit(s: string): number` (любая длина, `<` = 0);
существующая `checkDigit731` для 13 символов становится её частным случаем с проверкой длины.

Векторы для тестов:

| Строка | Сумма | Контрольная | Источник |
|---|---|---|---|
| `L898902C3` | 316 | 6 | образец паспорта из ICAO 9303 |
| `MP1234567` | 317 | 7 | ручной расчёт |
| `AB0000000` | 103 | 3 | ручной расчёт |
| `DP1234567` | 254 | 4 | ручной расчёт |
| `HB7654321` | 248 | 8 | ручной расчёт |

### Формат «Образца 1996 г.»

Источники: [Википедия](https://ru.wikipedia.org/wiki/Паспорт_гражданина_Республики_Беларусь),
[Миграпедия](https://ru.migrapedia.org/wiki/Паспорт_гражданина_Беларуси).

| Серия | Кем выдан |
|---|---|
| `AB` | Брестская область |
| `BM` | Витебская область |
| `HB` | Гомельская область |
| `KH` | Гродненская область |
| `MP` | г. Минск |
| `MC` | Минская область |
| `KB` | Могилёвская область |
| `PP` | МИД (гражданам, проживающим за границей) |
| `SP` | служебный паспорт |
| `DP` | дипломатический паспорт |

Таблица — одна константа данных в модуле формата.

- **Жёстко:** длина 9, структура `LLDDDDDDD`.
- **Мягко (предупреждение):** серия не из таблицы — «серия не из известного списка».
- **Разбор:** серия с расшифровкой (или «неизвестная серия»), номер, контрольная цифра MRZ.
- **Генерация:** поле «Серия» — выбор из таблицы (+ «Случайно»); поле «Номер» — 7 цифр.

### Формат «Биометрический (с 2021)»

Источник: постановление Совета Министров РБ от 31.05.2021 № 297 — «серийный номер бланка …
из двух букв латинского алфавита и семи арабских цифр»; для обычного паспорта серия указана
заглушкой «XX», для дипломатического — `DP`.

- **Жёстко:** длина 9, структура `LLDDDDDDD`.
- Серия: любые две латинские буквы; `DP` расшифровывается как «дипломатический паспорт»,
  остальные — «серия бланка (официально не опубликована)». Предупреждений о серии нет —
  список неизвестен, предупреждать не о чем.
- **Плашка:** «Серии бланков биометрических паспортов официально не опубликованы: постановление
  Совмина № 297 определяет только формат — две латинские буквы и семь цифр».
- **Разбор:** серия с расшифровкой, номер, контрольная цифра MRZ.
- **Генерация:** поле «Серия» — текст, две латинские буквы (кириллические двойники принимаются
  и заменяются); случайное значение — две случайные буквы `A–Z`; поле «Номер» — 7 цифр.

### Нормализация

Та же, что в первой фиче: пробелы, дефисы, невидимые символы удаляются, регистр приводится,
кириллические двойники заменяются с предупреждением. Все известные серии, кроме `SP` и `DP`,
целиком состоят из букв-двойников (`МР`, `НВ`, `КН`, `КВ`, `АВ`, `ВМ`, `МС`, `РР`).

Проверка структуры обобщается: `structureIssues(value, template)`, где шаблон из `D`/`L`
задаёт длину и классы символов. Идентификационный номер передаёт свой шаблон `DDDDDDDLDDDLLD`.

## Архитектура — изменения

```
src/
  core/
    checkDigit.ts        + icaoCheckDigit(s)
    structure.ts         structureIssues(value, template)
    types.ts             FormatId: string
  formats/
    passport1996.ts      новый
    passportBiometric.ts новый
    index.ts             реестр форматов -> по разделам; suggestOtherFormat(input, current, formats)
  tools/
    index.ts             категории и разделы
  ui/
    router.ts            разбор/сборка hash-маршрута (чистые функции) + подписка на hashchange
    sidebar.ts           боковое меню
    toolPage.ts          сборка страницы раздела
    formatState.ts       ключи по разделам, миграция старого ключа
    theme.css            + layout drawer
  main.ts                каркас: верхняя панель, меню, контейнер раздела
```

`router.ts` содержит только чистые функции разбора и сборки маршрута. Всё, что меняет URL
(`history.replaceState`, запись `location.hash`, удаление старого query) и хранилище, живёт в
`formatState.ts` — гарантия приватности по-прежнему проверяется на одном файле.

## Тестирование

Vitest:
- `icaoCheckDigit` — векторы из таблицы, включая образец ICAO; `<` = 0; `checkDigit731` по-прежнему
  отвергает длину ≠ 13;
- `structureIssues` с двумя шаблонами;
- `passport1996` — валидные номера, каждая жёсткая ошибка, неизвестная серия = предупреждение,
  кириллическая серия `МР1234567`, разбор, генерация из полей (`MP` + `1234567` → MRZ `7`),
  ошибки полей;
- `passportBiometric` — любая латинская серия валидна без предупреждений, `DP` расшифровывается,
  генерация случайной серии и из поля (включая кириллический ввод серии);
- свойство: 300 случайных номеров каждого формата проходят свою валидацию;
- роутер — разбор `#/passport-number?format=biometric`, пустой/неизвестный/«скоро» маршрут →
  раздел по умолчанию, перенос старого `?format=`;
- реестр — у каждого реализованного раздела ≥ 1 формат, id уникальны, категория существует;
- `formatState` — ключи по разделам, чтение старого ключа, отклонение формата чужого раздела;
- приватность — прежние правила на все файлы `src/`.

UI — ручная проверка в браузере: меню на 1280px и 400px (☰, scrim, Escape, фокус), переходы,
ссылка с форматом в новой вкладке, старая ссылка `?format=legacy`, паспорт в обоих форматах.

## Вне рамок

- ID-карта (MRZ TD1).
- Реализация УНП, IBAN, телефона — только пункты меню «скоро».
- Ввод номера паспорта вместе с контрольной цифрой MRZ (10 символов).

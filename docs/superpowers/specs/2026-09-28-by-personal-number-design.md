# by-data-tools — идентификационный номер РБ: дизайн

**Дата:** 2026-09-28
**Статус:** на согласовании

## Цель

Публичный веб-инструмент на GitHub Pages для валидации и генерации данных Республики Беларусь.
Первая фича — идентификационный (личный) номер паспорта: валидация, разбор на составляющие,
генерация (полностью случайная или по заданным полям).

**Аудитория:** QA и разработчики, которым нужны тестовые данные.
**Критерий успеха:** номер, сгенерированный инструментом, проходит валидацию по правилам
выбранного формата; валидатор не отвергает номер по правилу, которое не подтверждено
официально; введённый номер никуда не уходит из браузера.

## Решения, принятые в диалоге

- Репозиторий: `aquahitt/by-data-tools`, **публичный** (GitHub Pages на бесплатном плане).
- Стек: Vite + TypeScript + Vitest, компоненты `@material/web`.
- Дизайн: **material minimalism** — Material 3, светлая/тёмная тема по системной настройке,
  одна акцентная палитра, карточки без декора.
- Два формата номера, **выбираются пользователем явно** (без автоопределения).
- Реальных номеров для сверки нет (конфиденциальные данные) — тесты строятся на векторах,
  рассчитанных вручную по формуле МВД.

## Форматы

### Формат 2012+ — официальный

Источник: постановление МВД РБ от 18.10.2011 № 345 (п. 1 действует с 26.07.2013).

```
ЦЦЦЦЦЦЦ  Б  ЦЦЦ  ББ  Ц
   1     2   3    4   5
```

| Группа | Позиции | Правило |
|---|---|---|
| 1 | 1–7 | целое `7000000–7999999` |
| 2 | 8 | всегда `A` |
| 3 | 9–11 | номер последовательности, `000–999` |
| 4 | 12–13 | сигнатура, всегда `PB` |
| 5 | 14 | контрольная цифра |

Все правила — **жёсткие**: любое нарушение, включая несовпадение контрольной цифры, = номер невалиден.

### Формат до 2012 — неофициальный

Постановление № 345 его не описывает (п. 3: «сформированные ранее номера остаются неизменными»).
Структура взята из СМИ: [АиФ](https://aif.by/dontknows/kak_rasshifrovat_lichnyy_nomer_pasporta),
[onliner.by](https://forum.onliner.by/viewtopic.php?t=895870&start=160). Источники между собой
согласованы.

| Позиции | Смысл |
|---|---|
| 1 | пол и век: `1` м/XIX, `2` ж/XIX, `3` м/XX, `4` ж/XX, `5` м/XXI, `6` ж/XXI |
| 2–7 | дата рождения `DDMMYY`; век — из позиции 1 |
| 8 | регион: `A` г. Минск, `B` Минская обл., `C` Брестская, `E` Витебская, `H` Гомельская, `K` Гродненская, `M` Могилёвская |
| 9–11 | порядковый номер среди родившихся в тот же день, `000–999` |
| 12–13 | статус: `PB` гражданин РБ, `BA` лицо без гражданства, `BI` иностранный гражданин |
| 14 | контрольная цифра |

Таблицы регионов и статусов — **одна константа данных** в модуле формата, с ссылкой на источник.

Правила валидации:
- **жёсткие** (невалиден): длина и структура, первая цифра вне `1–6`, несуществующая дата
  (учёт високосных лет по полному году), неизвестный код региона или статуса;
- **мягкое** (предупреждение, номер остаётся валидным): контрольная цифра не совпадает с
  формулой 7-3-1. Формула для старых номеров официально не подтверждена, а отвергать реальный
  номер из-за неё нельзя.

В UI у формата постоянная плашка: «Структура и алгоритм контрольной цифры для номеров до 2012 года
официально не опубликованы».

Сгенерированные номера этого формата всё равно получают контрольную цифру по 7-3-1.

### Контрольная цифра (общая)

По п. 1.2–1.3 постановления № 345: первые 13 символов, веса `7,3,1` циклически слева направо,
буквы `A=10 … Z=35`, сумма произведений mod 10.

Векторы для тестов (посчитаны вручную):

| 13 символов | Сумма | Контрольная | Полный номер |
|---|---|---|---|
| `7000000A000PB` | 181 | 1 | `7000000A000PB1` |
| `7123456A789PB` | 356 | 6 | `7123456A789PB6` |

`3271182A001PB5`, который ходит в СМИ как «пример», по формуле даёт `1`, а не `5`, — **не используется
как валидная фикстура**.

## Нормализация ввода

Перед проверкой: `trim`, удаление пробелов и дефисов, приведение к верхнему регистру.

**Кириллица.** Буквы в игре — `A B C E H K M P` — имеют кириллических двойников `А В С Е Н К М Р`
(в самих СМИ пишут «РВ»). Кириллический двойник **заменяется на латиницу с видимым предупреждением**
«заменены кириллические символы: позиции 8, 12». Любая другая не-латинская буква — ошибка с
указанием позиции.

## Приватность

- Номер обрабатывается только в браузере; сетевых запросов с номером нет; аналитики нет.
- Номер **не пишется** в URL и в `localStorage`. Там хранится только выбранный формат.
- Шрифты и иконки — self-hosted (`@fontsource/roboto`, `material-symbols`), страница не делает
  запросов к сторонним хостам.

## Архитектура

```
src/
  core/
    checkDigit.ts        checkDigit731(s13): number
    normalize.ts         normalize(input): { value, warnings }
    random.ts            инжектируемый RNG (для детерминированных тестов)
    types.ts             FormatModule, ValidationResult, ParsedField, Issue
  formats/
    modern.ts            формат 2012+
    legacy.ts            формат до 2012 + таблицы регионов/статусов
    index.ts             реестр форматов
  ui/
    formatSwitch.ts      переключатель формата
    validatePanel.ts     валидация + разбор
    generatePanel.ts     генерация
    theme.css            токены M3, светлая/тёмная тема
  main.ts
index.html
```

Интерфейс формата — единый, UI от конкретного формата не зависит:

```ts
interface FormatModule<P> {
  id: 'modern' | 'legacy';
  title: string;
  official: boolean;
  validate(input: string): ValidationResult;   // errors[] (жёсткие) + warnings[] (мягкие)
  parse(input: string): ParsedField[] | null;  // поля для таблицы разбора
  generate(partial: Partial<P>, rng: Rng): string;
  fields: FieldSpec<P>[];                       // описание полей формы генерации
}
```

`ValidationResult`: `{ valid: boolean; normalized: string; errors: Issue[]; warnings: Issue[] }`,
`Issue`: `{ code, message, position? }`. Новые документы добавляются новым модулем в `formats/`.

## UI

Одна страница, три блока:

1. **Шапка** — название и переключатель формата: сегментированная кнопка **`2012+ (МВД № 345)` | `До 2012`**.
   `@material/web` держит segmented button только в `labs/` (нестабильно), поэтому переключатель
   — свой: `role="radiogroup"` из двух `<button role="radio">`, стилизованный токенами M3.
   Выбор хранится в `localStorage` и в URL (`?format=legacy`).
2. **Проверка и разбор** — поле ввода (`md-outlined-text-field`), кнопка «Проверить»
   (проверка также по мере ввода с debounce). Результат: статус (валиден / невалиден / валиден с
   предупреждениями), список ошибок и предупреждений с позициями, таблица разбора полей выбранного
   формата. Если номер не проходит выбранный формат, но проходит другой — подсказка
   «похоже на формат до 2012 года — переключить?».
3. **Генерация** — форма полей выбранного формата:
   - 2012+: группа 1 (`7000000–7999999`), номер последовательности;
   - до 2012: пол, дата рождения, регион (`md-outlined-select`), порядковый номер, статус.

   Кнопки: «Сгенерировать» (пустые поля заполняются случайно), «Всё случайно», кнопка
   случайного значения у каждого поля. Результат — номер крупно + «Копировать» + «Проверить»
   (переносит в блок 1). Некорректный ввод в поле (дата 31.02) — ошибка поля, генерация блокируется.

Интерфейс на русском. Адаптив до 400px ширины.

## Тестирование

Vitest, покрытие ядра и форматов:
- `checkDigit731` — ручные векторы из таблицы выше;
- `normalize` — пробелы, дефисы, регистр, кириллические двойники, чужие символы;
- `modern` — каждое жёсткое правило (первая цифра ≠ 7, позиция 8 ≠ A, сигнатура ≠ PB, неверная
  контрольная цифра), разбор;
- `legacy` — первая цифра вне 1–6, 29.02 в високосном/невисокосном году с учётом века, неизвестный
  регион/статус, несовпадение контрольной цифры = предупреждение, не ошибка;
- генерация — property-тест: N случайных номеров с фиксированным seed проходят `validate` без
  ошибок; генерация из заданных полей сохраняет их значения в разборе.

UI — smoke-проверка в браузере после сборки (не автотест в первой итерации).

## Сборка и деплой

- `vite.config.ts`: `base: '/by-data-tools/'` — иначе ассеты на project Pages отдают 404.
- GitHub Actions: `ci.yml` (lint + test + build на PR) и `pages.yml` (build + `actions/deploy-pages`
  на push в `main`).
- Источник Pages переключается на GitHub Actions явно
  (`POST /repos/aquahitt/by-data-tools/pages`, `build_type=workflow`) — `gh repo create` этого не делает.

## Вне рамок первой итерации

- Другие документы и данные РБ (УНП, IBAN, номера телефонов и т. п.) — следующими фичами через
  новый модуль в `formats/`.
- Пакетная генерация / экспорт CSV.
- i18n интерфейса.
